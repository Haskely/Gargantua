# 1. Intro

向我讲解一下浏览器里直接执行 shader 的技术历史和现状。

这是个非常有趣的问题，其实涉及了 **Web 浏览器里 GPU 编程（尤其是 shader）如何演进**的完整历史脉络。下面我分时间线来讲，从早期 hack 技术到现在主流的 WebGPU。

---

## 1. 前史：Shader 在浏览器外的世界

* **2001–2002**：DirectX 8 和 OpenGL ARB_fragment_program 引入可编程 shader，取代固定功能管线。
* **2005–2007**：桌面 GPU 逐渐普及，游戏和科研都开始用 shader 加速。
* 在这之前，浏览器里几乎没有“直接写 shader”的能力，能做的只有 Canvas 2D 的像素级操作。

---

## 2. 早期尝试：插件时代

* **Flash Stage3D (2011)**：Flash 11 引入 Stage3D API，开发者可以写类似 HLSL 的 AGAL（Adobe Graphics Assembly Language），运行在 GPU 上。
* **Java Applets / Unity Web Player**：通过插件，加载本地 OpenGL/DirectX，间接执行 shader。
* 局限：安全性低，需要安装插件，不是真正的浏览器原生。

---

## 3. WebGL：浏览器第一次原生支持 Shader

* **WebGL 1.0 (2011)**

  * 基于 OpenGL ES 2.0。
  * 引入 GLSL ES，开发者可以直接写 `vertex shader` 和 `fragment shader`，在浏览器中运行。
  * 核心突破：无需插件，JavaScript 就能调用 GPU。
  * 局限：只有顶点/片元 shader，没有几何/计算 shader。
* **WebGL 2.0 (2017)**

  * 基于 OpenGL ES 3.0。
  * 支持更多纹理格式、UBO、transform feedback、MRT 等，但仍然**没有 compute shader**。
  * 这导致开发者如果想做 GPGPU，要用“Framebuffer Ping-Pong”技巧：把计算编码进 fragment shader，存结果到纹理，再读出来。

---

## 4. WebGPU：现代 Shader 执行的正统方案

* **背景**

  * WebGL 长期基于 OpenGL，而桌面/移动 GPU 业界已经转向 Vulkan/Metal/DX12。
  * GPGPU 需求越来越大（机器学习、视频处理、科学计算）。
* **WebGPU (2023 W3C Candidate Recommendation)**

  * API 设计类似 Vulkan/Metal，跨平台。
  * 引入 **WGSL (WebGPU Shading Language)**，替代 GLSL，语法现代化、可验证安全。
  * 支持 **计算着色器 (compute shader)**，真正允许浏览器里直接做 GPU 通用计算。
  * 更好的性能模型，更接近原生 GPU API。
* **现状 (2025)**

  * 已经在 Chrome、Edge、Firefox、Safari（部分 behind flag）可用。
  * 机器学习框架（如 TensorFlow.js, WebLLM）、游戏引擎（Babylon.js, Unity WebGPU backend）都在用。
  * 被视为浏览器内 GPU 编程的未来标准。

---

## 5. “Shader Hack” 与实验性方案

在 WebGL 和 WebGPU 之间，还有一些创造性的 hack：

* **GLSL sandbox / Shadertoy (2013-)**

  * 利用 fragment shader 做 GPGPU，社区作品爆炸性增长。
  * 虽然是“渲染”，但实际上变成了一种 GPU 程序设计实验场。
* **GPU.js / Turbo.js**

  * 用 JavaScript 把计算转译成 WebGL shader，自动做 ping-pong。
  * 弥补了 WebGL 没有 compute shader 的缺陷。
* **WebAssembly + WebGPU**（近期趋势）

  * 高性能语言（Rust, C++）编译到 wasm，再调用 WebGPU 运行 shader。
  * 用于 AI 推理、科学计算。

---

## 6. 总结

* **插件时代 (2000s)**：Flash/Java，非原生。
* **WebGL 1.0/2.0 (2011–2017)**：浏览器首次原生支持 GLSL shader，但局限大。
* **Shader Hack (2010s)**：Shadertoy、GPU.js 等，用 fragment shader 伪造计算。
* **WebGPU (2023–现在)**：新一代 GPU API，原生支持 compute shader，WGSL 替代 GLSL，成为 AI 和图形的统一接口。

一句话：

> **今天，浏览器里“直接执行 shader”的主流方案是 WebGPU + WGSL，而 WebGL 仍然支撑着庞大的遗留生态。**
