## 1.1 什么是计算机图形学？

### 从现实世界到屏幕像素的魔法

计算机图形学（Computer Graphics）是研究如何用计算机生成、处理和显示图像的学科。听起来很抽象？让我们用一个简单的例子来理解。

想象一下，您正在玩一款赛车游戏。您看到：
- 🏎️ 一辆流线型的跑车在赛道上飞驰
- 🌅  夕阳的余晖洒在车身上，反射出金色的光芒
- 💨 车轮扬起的尘土随风飘散
- 🌲 道路两旁的树木快速向后退去

这一切看起来如此真实，但实际上，**屏幕上没有任何真实的物体**！您看到的只是数百万个发光的小点（像素）在以每秒60次的速度改变颜色。这就是计算机图形学的魔法 —— 通过精确计算每个像素的颜色，创造出逼真的视觉体验。

### 计算机图形学的应用领域

计算机图形学无处不在，它的应用远超您的想象：

**🎮 游戏娱乐**
- 3A游戏大作（如《赛博朋克2077》、《艾尔登法环》）
- 手机休闲游戏
- VR/AR虚拟现实体验

**🎬 影视制作**
- 电影特效（漫威电影中的超级英雄）
- 动画电影（皮克斯、迪士尼动画）
- 虚拟演播室

**🏗️ 专业应用**
- 建筑设计可视化
- 医学图像处理（CT、MRI扫描）
- 科学数据可视化
- 工业设计和仿真

**🌐 Web应用**
- 数据可视化图表
- 交互式3D产品展示
- 在线地图服务
- 网页动画效果

### 从2D到3D：维度的跨越

早期的计算机图形学主要处理2D图像 —— 简单的线条、形状和颜色。就像在纸上画画一样，只需要指定X（横坐标）和Y（纵坐标）两个维度。

但现实世界是三维的！为了创造更真实的视觉效果，我们需要加入第三个维度 —— Z（深度）。这就是3D图形学的核心：

- **X轴**：左右方向（横向）
- **Y轴**：上下方向（纵向）
- **Z轴**：前后方向（深度）

通过这三个坐标，我们可以在虚拟的三维空间中定位任何物体。

**💡 小贴士**：虽然我们的屏幕是2D的（只有宽和高），但通过巧妙的数学计算（投影变换），我们可以在2D屏幕上呈现3D场景的错觉。这就像画家用透视法在平面画布上创造立体感一样。

## 1.2 CPU vs GPU：为什么需要GPU？

### CPU：万能的总指挥

CPU（Central Processing Unit，中央处理器）是计算机的"大脑"。它非常聪明，可以处理各种复杂的任务：

- 📝 运行操作系统
- 🧮 执行复杂的计算
- 📂 管理文件系统
- 🌐 处理网络通信
- 🎯 协调各个硬件组件

CPU就像一位全能的总指挥，什么事情都能做，但它的核心数量有限（通常4-16个核心）。可以把CPU想象成一个**非常聪明的数学老师**：

- ✅ 可以解决各种复杂的问题
- ✅ 能够快速切换不同类型的任务
- ❌ 但如果要同时批改1000份试卷，速度就会很慢

### GPU：并行计算的专家

GPU（Graphics Processing Unit，图形处理器）是专门为图形计算设计的处理器。它的设计理念完全不同：

- 💪 拥有数千个小核心（而不是几个大核心）
- 🚀 擅长同时执行大量相似的简单计算
- 🎨 专为处理图形和并行任务优化

GPU就像一个**巨大的生产车间**，里面有成千上万个工人，每个人都在做同样的简单工作：

```
想象一个场景：
- CPU方式：1个非常快的工人，依次给1920×1080=2,073,600个像素上色
- GPU方式：2,073,600个工人，同时给所有像素上色！
```

### 为什么图形渲染需要GPU？

让我们用一个具体例子来理解：

假设您的屏幕分辨率是 **1920×1080**（全高清），每秒刷新 **60次**。这意味着：

```
每秒需要计算的像素数 = 1920 × 1080 × 60 = 124,416,000 次计算
```

**一亿两千万次计算**！而且每个像素的颜色可能都需要考虑：
- 💡 光照（光源位置、强度、颜色）
- 🪞 材质（金属、塑料、玻璃的反射特性）
- 🌫️ 阴影（物体之间的遮挡关系）
- 🎨 纹理（表面的图案和细节）

如果用CPU来做这些计算，即使是最强大的CPU也会不堪重负。但GPU可以轻松应对，因为它可以**同时**计算所有像素的颜色！

### CPU与GPU的工作分工

在现代图形应用中，CPU和GPU各司其职，紧密配合：

| 角色 | CPU（总指挥） | GPU（像素工厂） |
|------|--------------|----------------|
| **主要职责** | 游戏逻辑、物理计算、AI | 图形渲染、并行计算 |
| **工作方式** | 串行处理（一个接一个） | 并行处理（同时处理） |
| **擅长任务** | 复杂、多变的任务 | 简单、重复的任务 |
| **核心数量** | 少（4-16个） | 多（数千个） |
| **比喻** | 指挥家 | 合唱团 |

**实际工作流程**：
```
1. CPU决定需要画什么（场景中有哪些物体）
2. CPU准备数据（顶点位置、纹理、材质信息）
3. CPU将数据发送给GPU
4. GPU并行计算每个像素的颜色
5. GPU将最终图像显示在屏幕上
```

**⚠️ 注意事项**：
- CPU和GPU之间的数据传输是有开销的，所以我们要尽量减少不必要的数据传递
- 现代游戏和图形应用的性能优化，很大程度上就是在平衡CPU和GPU的工作负载

**💡 小贴士**：手机GPU虽然不如桌面显卡强大，但它们同样采用并行处理架构。这就是为什么现代手机能够流畅运行3D游戏的原因。

2. 为什么视频编辑、AI训练等任务也开始使用GPU？它们和图形渲染有什么共同点？

## 1.3 什么是着色器（Shader）？

### 给"像素工厂"编写指令的程序

如果说GPU是一个巨大的像素工厂，那么**着色器（Shader）**就是控制这个工厂如何工作的"操作手册"。

着色器是运行在GPU上的小程序，它告诉GPU：
- 🎯 物体的形状应该在屏幕的哪个位置
- 🎨 每个像素应该是什么颜色
- 💡 光线如何照射在物体表面
- 🪞 物体如何反射和折射光线

### 着色器不是"阴影"！

初学者常见的误解：Shader翻译成中文叫"着色器"，很容易让人以为它只是用来画阴影的。但实际上，**Shader控制着所有的视觉效果**，不仅仅是阴影！

更准确的理解是：
- **Shader = 给每个像素着色的程序**
- 它决定屏幕上每个小点的颜色、亮度、透明度

### 着色器的两大基本类型

在图形渲染中，最常用的是两种着色器：

#### 1️⃣ 顶点着色器（Vertex Shader）

**作用**：处理几何形状，确定物体在屏幕上的位置和形状

想象您要画一个三角形：
```
输入：三个顶点的3D坐标 (x, y, z)
  ↓
顶点着色器处理
  ↓
输出：三个顶点在屏幕上的2D位置
```

顶点着色器就像建筑工人，负责搭建物体的骨架：
- 📐 确定物体的形状和大小
- 🔄 处理物体的旋转和缩放
- 🎥 应用摄像机视角变换
- 🌊 创建动画效果（如水面波动）

#### 2️⃣ 片段着色器（Fragment Shader）/ 像素着色器（Pixel Shader）

**作用**：计算每个像素的最终颜色

当顶点着色器确定了形状后，片段着色器接手，为形状内部的每个像素上色：

```
输入：像素的位置信息
  ↓
片段着色器处理
  ↓
输出：这个像素的颜色 (R, G, B, A)
```

片段着色器就像画家，负责为建筑涂上颜色和纹理：
- 🎨 计算基础颜色
- 💡 模拟光照效果
- 🖼️ 应用纹理贴图
- ✨ 创造各种特效（如火焰、水波）

### 着色器工作流程示意

```
3D模型数据
    ↓
┌─────────────────┐
│ 顶点着色器       │ ← 处理每个顶点
│ (Vertex Shader) │   确定形状位置
└─────────────────┘
    ↓
  光栅化
    ↓
┌─────────────────┐
│ 片段着色器       │ ← 处理每个像素
│(Fragment Shader)│   确定像素颜色
└─────────────────┘
    ↓
  最终图像
```

### 着色器的强大之处

着色器之所以强大，是因为：

1. **并行执行**：每个顶点/像素的计算都是独立的，可以同时进行
2. **实时计算**：每一帧都重新计算，可以创造动态效果
3. **高度灵活**：通过编写不同的着色器代码，可以创造无限可能的视觉效果

**常见的着色器效果**：
- 🌊 水面波光粼粼
- 🔥 火焰燃烧效果
- 🌈 彩虹光晕
- 💎 金属和玻璃的真实质感
- 🌫️ 雾气和大气效果
- 📺 屏幕后处理（模糊、景深、色彩校正）

### 一个简单的类比

把着色器想象成一个配方：

```
顶点着色器 = 蛋糕模具
- 决定蛋糕的形状和大小
- 可以做圆形、方形、心形等

片段着色器 = 装饰步骤
- 决定蛋糕表面的颜色和纹理
- 可以加奶油、水果、巧克力等
```

每次烤蛋糕（渲染一帧），都会按照这个配方（着色器程序）来执行。改变配方，就能得到完全不同的结果！

**💡 小贴士**：现代GPU还支持其他类型的着色器，如几何着色器（Geometry Shader）、曲面细分着色器（Tessellation Shader）和计算着色器（Compute Shader）。但对于初学者，理解顶点和片段着色器就足够了。

## 1.4 图形渲染管线基础

### 从3D世界到2D屏幕的流水线

**渲染管线（Rendering Pipeline）**是一个将3D场景转换成2D屏幕图像的流程。它就像一条工厂的装配线：

```
原材料（3D数据）→ 多道工序 → 成品（屏幕图像）
```

每个环节都有特定的职责，环环相扣，最终产出我们在屏幕上看到的画面。

### 渲染管线的主要阶段

让我们通过一个简化的流程来理解：

#### 🎯 阶段1：应用阶段（CPU端）

这个阶段运行在CPU上，负责准备渲染所需的数据：

```
任务清单：
✓ 确定哪些物体需要绘制
✓ 准备顶点数据（位置、颜色、纹理坐标）
✓ 设置渲染状态（使用哪个着色器、开启哪些功能）
✓ 向GPU发送绘制命令
```

**类比**：就像厨师在炒菜前，先准备好所有食材和调料。

#### 🔺 阶段2：几何处理（顶点着色器）

顶点着色器处理每个顶点的位置变换：

```
输入：3D空间中的顶点坐标
  ↓
坐标变换（世界变换、视图变换、投影变换）
  ↓
输出：屏幕空间的2D坐标
```

**关键变换**：
- **模型变换**：物体在世界中的位置、旋转、缩放
- **视图变换**：从摄像机的角度观察世界
- **投影变换**：将3D场景"压扁"成2D图像（就像拍照）

**类比**：就像摄影师调整相机的位置和角度，决定最终照片的构图。

#### 🔲 阶段3：光栅化

光栅化是一个固定的（不可编程的）阶段，它的任务是：

```
输入：三角形的三个顶点
  ↓
判断哪些像素在三角形内部
  ↓
输出：需要着色的像素列表
```

**过程示意**：
```
想象一个三角形覆盖在像素网格上：

    ●--------●          ● = 顶点
     \      /           □ = 需要着色的像素
      \    /            ○ = 不需要着色的像素
       \  /
        ●

转换成：

○ ○ ○ □ □ □ ○ ○
○ ○ □ □ □ □ □ ○
○ □ □ □ □ □ □ □
○ ○ □ □ □ □ ○ ○
○ ○ ○ □ □ ○ ○ ○
```

**类比**：就像用模板喷漆，光栅化决定哪些区域会被喷上颜色。

#### 🎨 阶段4：像素处理（片段着色器）

片段着色器为每个像素计算最终颜色：

```
输入：像素位置、插值后的顶点属性
  ↓
颜色计算（纹理采样、光照计算、特效应用）
  ↓
输出：像素的最终颜色 (R, G, B, A)
```

**考虑因素**：
- 🎨 基础材质颜色
- 🖼️ 纹理贴图
- 💡 光照和阴影
- 🪞 反射和高光
- 🌫️ 透明度和混合

**类比**：就像画家为每个小格子精心调配颜色。

#### ✅ 阶段5：输出合并

最后阶段处理一些后期操作：

```
任务：
✓ 深度测试（哪个物体在前面？）
✓ 模板测试（特定区域的遮罩）
✓ 颜色混合（透明物体的叠加）
✓ 写入帧缓冲（最终显示的图像）
```

**类比**：就像照片的后期处理和输出。

### 完整流程图

```
┌──────────────────┐
│  应用阶段 (CPU)  │
│  准备数据和命令  │
└────────┬─────────┘
         ↓
┌──────────────────┐
│   顶点着色器     │ ← 可编程！
│   处理顶点位置   │
└────────┬─────────┘
         ↓
┌──────────────────┐
│   图元装配       │
│   组合成三角形   │
└────────┬─────────┘
         ↓
┌──────────────────┐
│     光栅化       │   固定功能
│   确定像素覆盖   │
└────────┬─────────┘
         ↓
┌──────────────────┐
│   片段着色器     │ ← 可编程！
│   计算像素颜色   │
└────────┬─────────┘
         ↓
┌──────────────────┐
│   输出合并       │
│  深度测试、混合  │
└────────┬─────────┘
         ↓
    📺 屏幕显示
```

### 可编程 vs 固定功能

渲染管线中有两类阶段：

**🔧 可编程阶段**（Programmable Stages）：
- 顶点着色器
- 片段着色器
- 开发者可以编写自定义代码
- 这就是我们学习WGSL的目标！

**⚙️ 固定功能阶段**（Fixed-Function Stages）：
- 光栅化
- 输出合并
- 由GPU硬件固定实现
- 可以配置参数但不能改变核心逻辑

### 为什么叫"管线"？

"管线"这个词非常形象：

1. **流水作业**：数据像流水一样，从一个阶段流向下一个阶段
2. **并行处理**：不同的数据可以同时处于管线的不同阶段
3. **高效执行**：一旦管线填满，每个时钟周期都有输出

**效率示意**：
```
时间 →
阶段1: [A] [B] [C] [D] ...
阶段2:     [A] [B] [C] ...
阶段3:         [A] [B] ...
阶段4:             [A] ...

一旦管线填满，每个周期都有一个完整的结果产出！
```

**💡 小贴士**：现代GPU的渲染管线比这里描述的要复杂得多，但核心思想是一样的。理解这个简化版本足以让您开始WebGPU编程。

**⚠️ 注意事项**：
- 管线中的瓶颈会影响整体性能。如果某个阶段太慢，整个管线都会被拖累
- 优化图形性能，往往就是在平衡各个管线阶段的工作负载

### 思考题

1. 如果一个场景中有10个物体，渲染管线需要运行多少次？
2. 为什么说顶点着色器和片段着色器是渲染管线中最重要的两个可编程阶段？

## 1.5 WebGPU简介和与WebGL的区别

### Web图形技术的演进之路

在了解WebGPU之前，让我们先回顾一下Web图形技术的发展历史：

#### 📅 时间轴

```
1995-2010: Flash时代
  └─ 插件式的动画和交互

2011: WebGL 1.0 发布
  └─ 基于OpenGL ES 2.0
  └─ 首次在浏览器中原生支持3D图形

2017: WebGL 2.0 发布
  └─ 基于OpenGL ES 3.0
  └─ 增强功能，但架构仍然较老

2021-现在: WebGPU
  └─ 现代化设计
  └─ 更接近GPU的底层能力
  └─ 支持图形和通用计算
```

### 什么是WebGPU？

**WebGPU**是新一代的Web图形API，它提供：

1. **更底层的GPU访问**
   - 直接暴露现代GPU的能力
   - 减少不必要的抽象层

2. **更好的性能**
   - 降低CPU开销
   - 更高效的资源管理
   - 更精细的控制

3. **统一的计算和图形**
   - 不仅能做图形渲染
   - 还能做通用GPU计算（GPGPU）
   - AI、科学计算、图像处理等

4. **跨平台一致性**
   - 统一的API设计
   - 在不同操作系统上行为一致

### WebGPU vs WebGL：主要区别

让我们通过对比来理解它们的不同：

#### 1️⃣ 设计理念

| 特性 | WebGL | WebGPU |
|------|-------|--------|
| **基于** | OpenGL ES（1990年代的设计） | 现代图形API（Vulkan/Metal/DirectX12） |
| **设计时间** | 2000年代 | 2020年代 |
| **状态管理** | 全局状态机（容易出错） | 显式的对象和命令 |
| **错误处理** | 同步错误检查（影响性能） | 异步验证（更高效） |

**类比**：
- **WebGL**像老式的手动挡汽车 —— 需要手动管理很多细节
- **WebGPU**像现代的电动车 —— 更智能的控制系统

#### 2️⃣ 着色器语言

| | WebGL | WebGPU |
|---|-------|--------|
| **语言** | GLSL (OpenGL Shading Language) | **WGSL (WebGPU Shading Language)** |
| **设计** | 基于C语言风格 | 现代、类型安全 |
| **示例** | `#version 300 es` | `@vertex fn main()` |

**WGSL的优势**：
- ✅ 更清晰的语法
- ✅ 强类型系统
- ✅ 更好的错误提示
- ✅ 现代特性支持

#### 3️⃣ 资源管理

**WebGL方式**（隐式状态）：
```javascript
// WebGL中，很多操作依赖于当前绑定的状态
gl.bindBuffer(gl.ARRAY_BUFFER, buffer);
gl.bufferData(gl.ARRAY_BUFFER, data, gl.STATIC_DRAW);
// 如果忘记绑定，可能会修改错误的buffer！
```

**WebGPU方式**（显式对象）：
```javascript
// WebGPU中，每个操作都明确指定操作的对象
const buffer = device.createBuffer({...});
device.queue.writeBuffer(buffer, 0, data);
// 更清晰，不会弄错！
```

#### 4️⃣ 命令提交

**WebGL**：
```
JavaScript调用 → 立即执行 → GPU
- 频繁的CPU-GPU通信
- 每个调用都有开销
```

**WebGPU**：
```
JavaScript调用 → 记录命令 → 批量提交 → GPU
- 命令编码器收集所有命令
- 一次性提交，减少开销
- 更高效！
```

#### 5️⃣ 计算能力

| 功能 | WebGL | WebGPU |
|------|-------|--------|
| **图形渲染** | ✅ 支持
 | ✅ 支持 |
| **通用计算** | ⚠️ 有限支持（通过变通方法） | ✅ 原生支持（Compute Shader） |
| **并行计算** | 困难 | 简单高效 |

**WebGPU的计算着色器**可以用于：
- 🧮 物理模拟
- 🤖 机器学习推理
- 🎨 图像处理
- 📊 数据分析

### 为什么选择WebGPU？

**现代化的设计**：
- 基于过去十年的图形API发展经验
- 吸收了Vulkan、Metal、DirectX 12的优点

**更好的性能**：

## 1.6 WGSL着色器语言介绍

### 现代化的着色器语言

**WGSL（WebGPU Shading Language）**是专门为WebGPU设计的着色器语言。它汲取了现有着色器语言（GLSL、HLSL、MSL）的优点，同时加入了现代编程语言的特性。

### 为什么需要新的着色器语言？

您可能会问：既然已经有GLSL了，为什么还要创造WGSL？

**主要原因**：

1. **统一性**
   - GLSL在不同平台上有细微差异
   - WGSL设计为跨平台一致
   - 一次编写，到处运行

2. **安全性**
   - 强类型系统
   - 编译时检查更严格
   - 减少运行时错误

3. **可读性**
   - 更清晰的语法
   - 现代化的代码风格
   - 更好的开发体验

4. **可移植性**
   - 可以编译到各种后端（Vulkan SPIR-V、Metal、D3D）
   - 保证行为一致

### WGSL语法概览

让我们通过一个简单的例子来感受WGSL的语法：

```wgsl
// 顶点着色器
@vertex
fn vertexMain(@builtin(vertex_index) vertexIndex: u32) -> @builtin(position) vec4f {
    // 定义三角形的三个顶点位置
    var positions = array<vec2f, 3>(
        vec2f(0.0, 0.5),   // 顶部
        vec2f(-0.5, -0.5),  // 左下
        vec2f(0.5, -0.5)    // 右下
    );

    // 返回当前顶点的位置（加上z=0和w=1）
    return vec4f(positions[vertexIndex], 0.0, 1.0);
}

// 片段着色器
@fragment
fn fragmentMain() -> @location(0) vec4f {
    // 返回红色
    return vec4f(1.0, 0.0, 0.0, 1.0); // RGBA
}
```

### WGSL核心特性

#### 1️⃣ 函数定义

```wgsl
// 函数语法：fn 函数名(参数) -> 返回类型
fn add(a: f32, b: f32) -> f32 {
    return a + b;
}

// 无返回值的函数
fn printMessage() {
    // ...
}
```

**特点**：
- 使用`fn`关键字
- 参数必须指定类型
- 返回类型明确声明

#### 2️⃣ 变量声明

```wgsl
// var声明（可变变量）
var x: f32 = 1.0;
x = 2.0; // ✅ 可以修改

// let声明（不可变变量）
let y: f32 = 1.0;
// y = 2.0; // ❌ 错误！不能修改

// const声明（编译时常量）
const PI: f32 = 3.14159;
```

**💡 小贴士**：优先使用`let`和`const`，只在确实需要修改时才用`var`。这是良好的编程习惯。

#### 3️⃣ 数据类型

**标量类型**：
```wgsl
var intValue: i32 = 42;        // 32位有符号整数
var uintValue: u32 = 42u;      // 32位无符号整数
var floatValue: f32 = 3.14;    // 32位浮点数
var boolValue: bool = true;    // 布尔值
```

**向量类型**：
```wgsl
var vec2Value: vec2f = vec2f(1.0, 2.0);           // 2D向量
var vec3Value: vec3f = vec3f(1.0, 2.0, 3.0);      // 3D向量
var vec4Value: vec4f = vec4f(1.0, 2.0, 3.0, 4.0); // 4D向量

// 访问向量分量
var x = vec3Value.x;  // 或 vec3Value.r
var y = vec3Value.y;  // 或 vec3Value.g
var z = vec3Value.z;  // 或 vec3Value.b

// Swizzling（重组分量）
var xy = vec3Value.xy;        // 获取x和y分量
var bgr = vec3Value.bgr;      // 重新排列为bgr
```

**矩阵类型**：
```wgsl
var mat2x2: mat2x2f;  // 2×2矩阵
var mat3x3: mat3x3f;  // 3×3矩阵
var mat4x4: mat4x4f;  // 4×4矩阵（常用于3D变换）
```

#### 4️⃣ 内置函数

WGSL提供了丰富的数学函数：

**基础数学**：
```wgsl
abs(x)      // 绝对值
min(a, b)   // 最小值
max(a, b)   // 最大值
clamp(x, min, max)  // 限制在范围内
```

**三角函数**：
```wgsl
sin(angle)   // 正弦
cos(angle)   // 余弦
tan(angle)   // 正切
```

**向量运算**：
```wgsl
length(v)        // 向量长度
normalize(v)     // 归一化（单位向量）
dot(a, b)        // 点积
cross(a, b)      // 叉积（仅3D向量）
distance(a, b)   // 两点距离
```

**插值和混合**：
```wgsl
mix(a, b, t)     // 线性插值：a*(1-t) + b*t
smoothstep(edge0, edge1, x)  // 平滑插值
```

#### 5️⃣ 属性（Attributes）

属性用于标记函数和参数的特殊用途：

```wgsl
// 标记入口点
@vertex      // 顶点着色器入口
@fragment    // 片段着色器入口
@compute     // 计算着色器入口

// 内置变量
@builtin(position)        // 输出位置
@builtin(vertex_index)    // 顶点索引
@builtin(instance_index)  // 实例索引

// 位置标记
@location(0)  // 第0个输入/输出位置

// 绑定组和绑定点
@group(0) @binding(0)  // 资源绑定位置
```

#### 6️⃣ 结构体

```wgsl
// 定义结构体
struct VertexOutput {
    @builtin(position) position: vec4f,
    @location(0) color: vec4f,
    @location(1) uv: vec2f,
}

// 使用结构体
@vertex
fn vertexMain() -> VertexOutput {
    var output: VertexOutput;
    output.position = vec4f(0.0, 0.0, 0.0, 1.0);
    output.color = vec4f(1.0, 0.0, 0.0, 1.0);
    output.uv = vec2f(0.0, 0.0);
    return output;
}
```

### WGSL vs GLSL 对比

让我们看一个对比示例，理解WGSL相比GLSL的改进：

**GLSL（WebGL）**：
```glsl
#version 300 es
precision mediump float;

in vec2 vUV;
out vec4 fragColor;

uniform sampler2D uTexture;

void main() {
    fragColor = texture(uTexture, vUV);
}
```

**WGSL（WebGPU）**：
```wgsl
@group(0) @binding(0) var textureSampler: sampler;
@group(0) @binding(1) var textureData: texture_2d<f32>;

@fragment
fn fragmentMain(@location(0) uv: vec2f) -> @location(0) vec4f {
    return textureSample(textureData, textureSampler, uv);
}
```

**主要区别**：
- ✅ 不需要版本声明和精度声明
- ✅ 更明确的资源绑定（`@group`、`@binding`）
- ✅ 函数名称可以自定义（不必是`main`）
- ✅ 类型后缀更清晰（`vec2f`而不是`vec2`）

### 学习WGSL的建议

**对于初学者**：
1. 先理解基本概念（变量、函数、类型）
2. 从简单的着色器开始（纯色、简单动画）
3. 逐步学习数学函数
4. 多看示例代码，多实践

**常见陷阱**：
- ⚠️ 忘记类型后缀（写`vec2`而不是`vec2f`）
- ⚠️ 混淆`var`、`let`、`const`的使用场景
- ⚠️ 忘记添加必要的属性标记

**💡 小贴士**：WGSL的官方规范很详细，遇到问题时可以查阅。但对于入门，理解本章的基础知识就足够了。

## 本章总结

恭喜您完成第一章的学习！让我们回顾一下您学到的核心概念：

### 🎯 关键知识点

1. **计算机图形学基础**
   - 图形学是通过计算像素颜色来创造视觉体验的科学
   - 应用广泛：游戏、影视、设计、科学计算等

2. **CPU vs GPU**
   - CPU：串行处理，擅长复杂逻辑
   - GPU：并行处理，擅长大量简单计算
   - 图形渲染需要GPU的并行能力

3. **着色器（Shader）**
   - 运行在GPU上的程序
   - 顶点着色器：处理几何形状和位置
   - 片段着色器：计算每个像素的颜色

4. **渲染管线**
   - 从3D数据到2D图像的流水线
   - 可编程阶段：顶点和片段着色器
   - 固定功能阶段：光栅化、输出合并

5. **WebGPU**
   - 现代Web图形API
   - 相比WebGL更底层、更高效
   - 支持图形渲染和通用计算

6. **WGSL**
   - WebGPU的着色器语言
   - 现代化、类型安全、跨平台
   - 清晰的语法和强大的功能

7. **开发环境**
   - 浏览器：Chrome 113+推荐
   - 编辑器：VSCode + WGSL扩展
   - 服务器：Live Server或Python
