
# 第四章：片段着色器的魔法世界

## 引言

在前面的章节中，我们学习了如何设置WebGPU环境和顶点着色器的工作原理。现在，我们将深入探索渲染管线中最具创造性的部分——片段着色器（Fragment Shader）。如果说顶点着色器决定了几何形状的位置，那么片段着色器就是决定每个像素颜色的魔法师。

在本章中，我们将详细分析`study/3.wgsl_mini_demo/index.html`中的片段着色器代码，这是一个展示交互式颜色动画和波纹效果的完整示例。

## 4.1 片段着色器基础概念

### 4.1.1 什么是片段着色器？

片段着色器是GPU渲染管线中的关键组件，它的工作是为屏幕上的每个像素（准确地说是每个片段）计算最终的颜色值。想象一下，你正在给一幅巨大的画布上色，片段着色器就像是一个超级快速的画家，能够同时为成千上万个像素点上色。

**关键特点：**
- **逐像素执行**：片段着色器会为渲染目标的每个像素独立执行一次
- **高度并行**：GPU可以同时处理成千上万个像素，这就是GPU强大的原因
- **颜色计算**：片段着色器的核心任务是计算并返回一个颜色值

### 4.1.2 片段着色器在渲染管线中的位置

渲染管线的执行流程：

```
顶点数据 → 顶点着色器 → 光栅化 → 片段着色器 → 输出到屏幕
```

1. **顶点着色器**：处理顶点位置（我们在第3章学过）
2. **光栅化**：将几何图形转换为像素片段
3. **片段着色器**：为每个片段计算颜色（本章的重点）
4. **输出合并**：将最终颜色写入帧缓冲区

### 4.1.3 UV坐标系统

在片段着色器中，我们经常使用UV坐标来确定像素在纹理或屏幕空间中的位置。

**UV坐标特点：**
- U轴：水平方向，范围通常是0.0到1.0
- V轴：垂直方向，范围通常是0.0到1.0
- 原点(0,0)：通常在左下角
- 终点(1,1)：通常在右上角

```
(0,1) ----------- (1,1)
  |                 |
  |     UV空间      |
  |                 |
(0,0) ----------- (1,0)
```

## 4.2 片段着色器代码详解

让我们逐行分析`index.html`文件第136-163行的片段着色器代码：

### 4.2.1 函数声明

```wgsl
@fragment
fn fragmentMain(input: VertexOutput) -> @location(0) vec4f {
```

**代码解析：**

- `@fragment`：这是一个**装饰器**（attribute），告诉WebGPU这是片段着色器的入口函数
- `fn fragmentMain`：函数名，可以自定义，但必须与管线配置中的入口点名称匹配
- `input: VertexOutput`：输入参数，接收来自顶点着色器的插值数据
  - `VertexOutput`是我们在顶点着色器中定义的输出结构体
  - GPU会自动对顶点之间的数据进行插值
- `-> @location(0) vec4f`：返回值类型
  - `@location(0)`：指定输出到第一个渲染目标（通常是屏幕）
  - `vec4f`：4维浮点向量，表示RGBA颜色（红、绿、蓝、透明度）

### 4.2.2 获取UV坐标

```wgsl
// 获取当前像素的 UV 坐标
let uv = input.uv;
```

**代码解析：**

- `let uv`：声明一个不可变变量（WGSL中的`let`类似于其他语言的`const`）
- `input.uv`：从顶点着色器传递过来的UV坐标
- 这个UV坐标已经由GPU自动插值，每个像素都有唯一的UV值

**举例说明：**
- 屏幕左下角的像素：`uv = (0.0, 0.0)`
- 屏幕中心的像素：`uv = (0.5, 0.5)`
- 屏幕右上角的像素：`uv = (1.0, 1.0)`

### 4.2.3 获取时间参数

```wgsl
// 基于时间创建动画效果
let t = uniforms.time;
```

**代码解析：**

- `uniforms.time`：从CPU传递过来的时间值（以秒为单位）
- 这个值会随着每一帧的渲染不断增加，创造动画效果
- Uniform变量在所有像素中都是相同的值

## 4.3 Uniform变量详解

在继续讲解颜色计算之前，我们需要理解uniform变量的概念。

### 4.3.1 Uniform结构体定义（第90-95行）

```wgsl
struct Uniforms {
    time: f32,        // 时间（秒）
    mouseX: f32,      // 鼠标 X 坐标（归一化到 0-1）
    mouseY: f32,      // 鼠标 Y 坐标（归一化到 0-1）
    padding: f32,     // 填充字节，确保 16 字节对齐
}
```

**字段说明：**

1. **time: f32**
   - 存储自程序启动以来的时间（秒）
   - 用于创建时间相关的动画效果
   - 每帧更新一次

2. **mouseX: f32**
   - 鼠标的水平位置，归一化到0.0-1.0范围
   - 0.0 = 屏幕最左侧
   - 1.0 = 屏幕最右侧

3. **mouseY: f32**
   - 鼠标的垂直位置，归一化到0.0-1.0范围
   - 0.0 = 屏幕最下方
   - 1.0 = 屏幕最上方

4. **padding: f32**
   - 填充字节，用于满足GPU的内存对齐要求
   - GPU要求uniform数据按16字节对齐
   - 3个f32 = 12字节，需要额外4字节才能达到16字节

### 4.3.2 Uniform绑定声明（第98行）

```wgsl
@group(0) @binding(0) var<uniform> uniforms: Uniforms;
```

**代码解析：**

- `@group(0)`：绑定组索引，可以有多个绑定组（0, 1, 2...）
- `@binding(0)`：在该组内的绑定点索引
- `var<uniform>`：声明这是一个uniform变量（所有像素共享同一个值）
- `uniforms: Uniforms`：变量名为`uniforms`，类型为`Uniforms`结构体

**Uniform vs Varying的区别：**

| 特性 | Uniform变量 | Varying变量（如UV） |
|------|------------|-------------------|
| 值的变化 | 所有像素相同 | 每个像素不同（插值） |
| 更新频率 | CPU控制，每帧或按需更新 | GPU自动插值 |
| 典型用途 | 时间、鼠标位置、变换矩阵 | UV坐标、颜色、法线 |

## 4.4 颜色计算的数学魔法

现在我们来详细分析RGB三个颜色通道是如何计算的。

### 4.4.1 R通道（红色）计算

```wgsl
// R 通道：基于 UV.x 和时间的正弦波
let r = sin(uv.x * 3.14159 + t) * 0.5 + 0.5;
```

**数学分解：**

1. **`uv.x * 3.14159`**：
   - `uv.x`的范围是0.0到1.0
   - 乘以π（3.14159），将范围映射到0到π
   - 这意味着从左到右经历一个半周期的正弦波

2. **`+ t`**：
   - 加上时间值，使正弦波随时间移动
   - 创建从左向右移动的波动效果

3. **`sin(...)`**：
   - 正弦函数的输出范围是-1.0到1.0
   - 创建周期性的波动

4. **`* 0.5 + 0.5`**：
   - 将-1.0到1.0的范围重新映射到0.0到1.0
   - 公式：`output = (input + 1.0) / 2.0 = input * 0.5 + 0.5`
   - 这样确保颜色值在有效范围内

**视觉效果：**
- 水平方向上呈现波浪形的红色渐变
- 波浪随时间从左向右流动
- 创建动态的"呼吸"效果

**数学可视化：**
```
sin(x)原始波形（范围 -1 到 1）：
    1 |     ╱╲      ╱╲
      |    ╱  ╲    ╱  ╲
    0 |___╱____╲__╱____╲___
      |        ╲╱      ╲╱
   -1 |

经过 * 0.5 + 0.5 后（范围 0 到 1）：
    1 |   ╱╲    ╱╲
      |  ╱  ╲  ╱  ╲
  0.5 |_╱____╲╱____╲_
      |
    0 |
```

### 4.4.2 G通道（绿色）计算

```wgsl
// G 通道：基于 UV.y 和鼠标 Y 位置的余弦波
let g = cos(uv.y * 3.14159 + uniforms.mouseY * 6.28) * 0.5 + 0.5;
```

**数学分解：**

1. **`uv.y * 3.14159`**：
   - 使用垂直坐标，从下到上变化
   - 创建垂直方向的波动

2. **`uniforms.mouseY * 6.28`**：
   - `6.28`约等于2π
   - 鼠标Y位置会影响波的相位
   - 移动鼠标会改变绿色分布

3. **`cos(...)`**：
   - 使用余弦而不是正弦
   - 余弦是正弦的相位偏移版本
   - `cos(x) = sin(x + π/2)`

4. **`* 0.5 + 0.5`**：
   - 同样将范围映射到0.0-1.0

**视觉效果：**
- 垂直方向的绿色渐变
- 鼠标上下移动会改变绿色的分布模式
- 与红色通道结合产生复杂的颜色变化

**交互性：**
- 鼠标在屏幕底部（mouseY ≈ 0）：绿色分布是一种模式
- 鼠标在屏幕中间（mouseY ≈ 0.5）：绿色分布发生明显变化
- 鼠标在屏幕顶部（mouseY ≈ 1）：绿色分布又是另一种模式

### 4.4.3 B通道（蓝色）计算

```wgsl
// B 通道：基于鼠标 X 位置和时间
let b = sin(uniforms.mouseX * 6.28 + t * 0.5) * 0.5 + 0.5;
```

**数学分解：**

1. **`uniforms.mouseX * 6.28`**：
   - 鼠标水平位置控制蓝色的主要变化
   - 乘以2π，在0-2π范围内变化

2. **`+ t * 0.5`**：
   - 时间以一半的速度影响蓝色
   - `* 0.5`使蓝色变化比红色慢
   - 创建不同频率的动画效果

3. **`sin(...)`**：
   - 正弦函数创建周期性变化

4. **`* 0.5 + 0.5`**：
   - 范围归一化

**视觉效果：**
- 蓝色在整个屏幕上均匀分布（不依赖UV）
- 鼠标左右移动会改变蓝色的强度
- 随时间缓慢脉动（比红色慢一半）

**特殊之处：**
- 这是唯一不直接使用UV坐标的颜色通道
- 在整个屏幕上蓝色值是统一的（但会随时间和鼠标变化）
- 创建全局的色调变化

### 4.4.4 为什么使用 sin 和 cos？

**周期性函数的优势：**

1. **平滑变化**：
   - sin和cos函数是连续且平滑的
   - 没有突变或锐角，视觉效果柔和

2. **自然循环**：
   - 周期性函数会自然地循环
   - 时间可以无限增长，颜色会周期性地重复

3. **数学可预测性**：
   - 容易计算和调整
   - 可以通过改变参数精确控制效果

4. **GPU友好**：
   - GPU对三角函数有硬件加速
   - 执行速度非常快

## 4.5 波纹效果的实现

波纹效果是这个演示中最精彩的部分，它创造了从鼠标位置向外扩散的涟漪效果。

### 4.5.1 距离计算

```wgsl
// 添加一些波纹效果
let dist = distance(uv, vec2f(uniforms.mouseX, uniforms.mouseY));
```

**代码解析：**

1. **`distance()`函数**：
   - WGSL内置函数，计算两点之间的欧几里得距离
   - 数学公式：`distance(p1, p2) = sqrt((p2.x - p1.x)² + (p2.y - p1.y)²)`

2. **`uv`**：
   - 当前像素的位置（范围0-1）

3. **`vec2f(uniforms.mouseX, uniforms.mouseY)`**：
   - 鼠标的位置（范围0-1）
   - 创建一个二维向量

4. **`dist`的含义**：
   - 当前像素到鼠标位置的距离
   - 范围约为0到1.414（对角线距离）
   - 距离越小，像素离鼠标越近

**距离可视化：**

```
鼠标位置在(0.5, 0.5)时的距离分布：

(0,1) ← 0.7 ← 0.5 ← 0.7 → (1,1)
  ↓       ↓      ↓      ↓      ↓
 0.7     0.5    0.0    0.5    0.7
  ↓       ↓      ↓      ↓      ↓
 0.5     0.3   [鼠标]  0.3    0.5
  ↓       ↓      ↓      ↓      ↓
 0.7     0.5    0.0    0.5    0.7
  ↓       ↓      ↓      ↓      ↓
(0,0) ← 0.7 ← 0.5 ← 0.7 → (1,0)

数字表示到鼠标的距离（近似值）
```

### 4.5.2 波纹计算

```wgsl
let wave = sin(dist * 20.0 - t * 3.0) * 0.2 + 0.8;
```

这是整个效果的核心！让我们详细分解：

**数学分解：**

1. **`dist * 20.0`**：
   - 将距离放大20倍
   - 较小的距离变化会导致更明显的相位差异
   - 这个系数控制波纹的"密度"（越大，波纹越密集）

2. **`- t * 3.0`**：
   - 减去时间的3倍
   - 负号表示波纹向外扩散（从中心向外）
   - 3.0控制波纹扩散的速度

3. **`sin(...)`**：
   - 创建周期性的波动
   - 在距离上产生明暗相间的环形图案

4. **`* 0.2 + 0.8`**：
   - 将-1到1映射到0.6到1.0
   - 波纹不会完全变黑（最暗只到0.6）
   - 0.2控制波纹的"强度"（幅度）
   - 0.8是基准值（平均亮度）

**波纹原理：**

```
时间 t=0 时：
  鼠标附近(dist小) → dist*20小 → sin值根据位置变化
  远离鼠标(dist大) → dist*20大 → sin值随距离震荡

时间 t=1 时：
  整个sin函数向左移动（-t*3.0变大）
  效果：波纹向外扩散

时间 t=2 时：
  继续向外扩散...
```

**参数调整效果：**

| 参数 | 效果 |
|------|------|
| `dist * 20.0` | 20越大，波纹越密集；越小，波纹越稀疏 |
| `t * 3.0` | 3越大，扩散越快；越小，扩散越慢 |
| `* 0.2` | 0.2越大，波纹对比度越强；越小，效果越微妙 |
| `+ 0.8` | 0.8越大，整体越亮；越小，整体越暗 |

### 4.5.3 波纹的数学推导

让我们从数学角度理解波纹效果：

**1. 径向波的一般形式：**
```
wave(r, t) = A * sin(k*r - ω*t + φ) + B
```
其中：
- r = 距离（我们的dist）
- t = 时间
- A = 振幅（我们的0.2）
- k = 波数（我们的20.0），控制空间频率
- ω = 角频率（我们的3.0），控制时间频率
- φ = 初始相位（我们设为0）
- B = 偏移量（我们的0.8）

**2. 波的传播速度：**
```
v = ω / k = 3.0 / 20.0 = 0.15 单位/秒
```
这表示波纹以每秒0.15个单位的速度向外扩散。

**3. 波长：**
```
λ = 2π / k = 2π / 20.0 ≈ 0.314 单位
```
相邻波峰之间的距离约为0.314个单位（在0-1的UV空间中）。

## 4.6 颜色组合与输出

### 4.6.1 颜色组合

```wgsl
// 组合最终颜色
let color = vec3f(r, g, b) * wave;
```

**代码解析：**

1. **`vec3f(r, g, b)`**：
   - 创建一个三维向量，表示RGB颜色
   - r、g、b分别是之前计算的红、绿、蓝通道值
   - 范围都在0.0-1.0之间

2. **`* wave`**：
   - 将RGB颜色乘以波纹值（标量乘法）
   - 相当于 `vec3f(r * wave, g * wave, b * wave)`
   - 波纹效果影响所有颜色通道，创建明暗变化

**效果说明：**
- 在波峰处（wave接近1.0）：颜色接近原始RGB值，较亮
- 在波谷处（wave接近0.6）：颜色被减弱到60%，较暗
- 这创造了从鼠标位置向外扩散的明暗涟漪

### 4.6.2 最终颜色输出

```wgsl
// 返回 RGBA 颜色（alpha = 1.0 表示完全不透明）
return vec4f(color, 1.0);
```

**代码解析：**

1. **`vec4f(color, 1.0)`**：
   - 从vec3f扩展到vec4f
   - 前三个分量是RGB（来自color变量）
   - 第四个分量是Alpha（透明度）

2. **Alpha = 1.0**：
   - 1.0表示完全不透明
   - 0.0表示完全透明
   - 中间值表示半透明

3. **返回值**：
   - 这个vec4f颜色会被写入到渲染目标（屏幕）
   - GPU会自动处理颜色混合和显示

**RGBA颜色结构：**
```
vec4f(R, G, B, A)
      │  │  │  └─ Alpha: 透明度 (0.0-1.0)
      │  │  └──── Blue:  蓝色分量 (0.0-1.0)
      │  └─────── Green: 绿色分量 (0.0-1.0)
      └────────── Red:   红色分量 (0.0-1.0)
```

## 4.7 完整代码流程总结

让我们回顾整个片段着色器的执行流程：

```wgsl
@fragment
fn fragmentMain(input: VertexOutput) -> @location(0) vec4f {
    // 步骤1：获取基础数据
    let uv = input.uv;                    // 当前像素的UV坐标
    let t = uniforms.time;                // 当前时间

    // 步骤2：计算RGB三个颜色通道
    let r = sin(uv.x * 3.14159 + t) * 0.5 + 0.5;                    // 红色
    let g = cos(uv.y * 3.14159 + uniforms.mouseY * 6.28) * 0.5 + 0.5; // 绿色
    let b = sin(uniforms.mouseX * 6.28 + t * 0.5) * 0.5 + 0.5;      // 蓝色

    // 步骤3：计算波纹效果
    let dist = distance(uv, vec2f(uniforms.mouseX, uniforms.mouseY)); // 距离
    let wave = sin(dist * 20.0 - t * 3.0) * 0.2 + 0.8;               // 波纹

    // 步骤4：组合颜色和波纹
    let color = vec3f(r, g, b) * wave;

    // 步骤5：输出最终颜色
    return vec4f(color, 1.0);
}
```

**数据流向图：**

```
输入数据:
  ├─ uv (来自顶点着色器插值)
  └─ uniforms (来自CPU)
       ├─ time
       ├─ mouseX
       └─ mouseY

颜色计算:
  ├─ R通道 ← sin(uv.x + time)
  ├─ G通道 ← cos(uv.y + mouseY)
  └─ B通道 ← sin(mouseX + time)

效果叠加:
  ├─ 计算距离 ← distance(uv, mouse)
  ├─ 计算波纹 ← sin(distance - time)
  └─ 应用波纹 ← RGB * wave

输出:
  └─ vec4f(R, G, B, 1.0) → 屏幕像素
```

## 4.10 性能优化技巧

### 4.10.1 避免重复计算

**不好的做法：**
```wgsl
let color1 = sin(uv.x * 3.14159 + uniforms.time) * 0.5 + 0.5;
let color2 = sin(uv.x * 3.14159 + uniforms.time) * 0.3 + 0.7;
```

**好的做法：**
```wgsl
let base = sin(uv.x * 3.14159 + uniforms.time);
let color1 = base * 0.5 + 0.5;
let color2 = base * 0.3 + 0.7;
```

### 4.10.2 使用内置函数

GPU对内置函数有硬件加速，优先使用它们：

**不好的做法：**
```wgsl
let dist = sqrt(pow(uv.x - 0.5, 2.0) + pow(uv.y - 0.5, 2.0));
```

**好的做法：**
```wgsl
let dist = distance(uv, vec2f(0.5, 0.5));
```

### 4.10.3 避免分支

GPU在处理分支时效率较低，尽量使用数学函数代替：

**不好的做法：**
```wgsl
var result: f32;
if (uv.x > 0.5) {
    result = 1.0;
} else {
    result = 0.0;
}
```

**好的做法：**
```wgsl
let result = step(0.5, uv.x);  // x > 0.5 时返回1.0，否则返回0.0
```

### 4.10.4 预计算常量

将不变的计算移到CPU端：

**不好的做法：**
```wgsl
let value = sin(uv.x * 3.14159265359);
```

**好的做法：**
在uniform中传递预计算的PI值，或使用const：
```wgsl
const PI = 3.14159;
let value = sin(uv.x * PI);
```

## 4.12 常见问题解答

### Q1：为什么颜色看起来不对？

**A**：检查以下几点：
1. 颜色值是否在0.0-1.0范围内
2. 是否正确使用了`* 0.5 + 0.5`来映射sin/cos的输出
3. Alpha通道是否设置为1.0
4. 是否有除以零的情况

### Q2：如何创建平滑的渐变？

**A**：使用`smoothstep`函数：
```wgsl
// 从0.3到0.7之间平滑过渡
let gradient = smoothstep(0.3, 0.7, uv.x);
return vec4f(gradient, gradient, gradient, 1.0);
```

### Q3：如何实现颜色混合？

**A**：使用`mix`函数：
```wgsl
let color1 = vec3f(1.0, 0.0, 0.0);  // 红色
let color2 = vec3f(0.0, 0.0, 1.0);  // 蓝色
let mixed = mix(color1, color2, uv.x);  // 水平渐变
return vec4f(mixed, 1.0);
```

### Q4：波纹效果不明显怎么办？

**A**：调整以下参数：
1. 增大振幅：将`* 0.2`改为`* 0.5`或更大
2. 增加密度：将`dist * 20.0`改为`dist * 40.0`
3. 调整基准值：将`+ 0.8`改为`+ 0.5`使对比度更强

### Q5：如何创建循环动画？

**A**：使用模运算或三角函数：
```wgsl
// 方法1：使用fract
let t = fract(uniforms.time / 2.0);  // 每2秒循环一次

// 方法2：使用sin/cos（自然循环）
let t = sin(uniforms.time) * 0.5 + 0.5;
```
